# 05-11 存储

> 对应源码：`src/store/store.ts`、`src/store/json-store.ts`

## 1. 角色定位

存储**会话映射**：`sessionKey → { sessionFile, cwd, chatType, chatId, ... }`。
这是「进程重启后还能恢复会话」的关键——Pi 的 session 文件在磁盘上，
但「哪个飞书会话对应哪个 session 文件」这层映射必须自己持久化。

## 2. 存储抽象（store.ts）

```ts
export function createStore(config: FeishuConfig): FeishuStore {
  if (config.sessions.store === "sqlite") {
    throw new Error("SQLite store is not implemented yet; use sessions.store = \"json\"");
  }
  const baseDir = config.files.tempDir ?? ".";
  return new JsonFeishuStore(join(baseDir, "sessions.json"));
}
```

- 工厂函数：根据配置选择实现
- SQLite 未实现 → 语义化报错（和 webhook 一样的占位策略）
- JSON 实现：文件放在 `tempDir/sessions.json`

**接口先行**：`FeishuStore` 接口定义在 types.ts，业务代码只依赖接口。
将来换 SQLite 只需要新写一个类，调用方零改动（详见 08 的演进路径）。

## 3. FeishuStore 接口

```ts
export interface FeishuStore {
  getSessionMapping(sessionKey: string): Promise<SessionMapping | undefined>;
  setSessionMapping(mapping: SessionMapping): Promise<void>;
  deleteSessionMapping(sessionKey: string): Promise<void>;
  listSessionMappings(filter?: SessionFilter): Promise<SessionMapping[]>;
}
```

四个方法覆盖完整 CRUD：单查、写、删、列表（带过滤）。

## 4. JsonFeishuStore：JSON 文件实现

### 4.1 文件结构

```ts
interface StoreFile {
  mappings: SessionMapping[];
}
```

整个文件就是一个 `{ mappings: [...] }` 数组，JSON 序列化写入。

### 4.2 写入串行化：withWriteLock

```ts
private writeTail: Promise<void> = Promise.resolve();

private async withWriteLock(run: () => Promise<void>): Promise<void> {
  const previous = this.writeTail;
  let release: () => void = () => {};
  this.writeTail = new Promise<void>((resolve) => { release = resolve; });
  await previous;
  try {
    await run();
  } finally {
    release();
  }
}
```

**这是 PromptQueue 同一个手法的复用**——Promise 链串行化。
为什么要串行？因为「读文件 → 改内存数组 → 写文件」不是原子的，
并发写会互相覆盖（read-modify-write 竞态）。
`withWriteLock` 保证写操作一个接一个，**读操作可以并发**（不加锁，只读不冲突）。

### 4.3 setSessionMapping

```ts
async setSessionMapping(mapping: SessionMapping): Promise<void> {
  await this.withWriteLock(async () => {
    const file = await this.readStore();
    const index = file.mappings.findIndex((entry) => entry.sessionKey === mapping.sessionKey);
    if (index === -1) {
      file.mappings.push(mapping);        // 新增
    } else {
      file.mappings[index] = mapping;     // 覆盖（upsert 语义）
    }
    await this.writeStore(file);
  });
}
```

upsert 语义：按 sessionKey 查重，有则替换，无则追加。

### 4.4 readStore：容错读取

```ts
private async readStore(): Promise<StoreFile> {
  try {
    const raw = await readFile(this.filePath, "utf-8");
    const parsed = JSON.parse(raw) as unknown;
    if (isStoreFile(parsed)) {
      return { mappings: parsed.mappings as SessionMapping[] };
    }
  } catch (error) {
    if (error instanceof Error && "code" in error && error.code === "ENOENT") {
      return { mappings: [] };           // 文件不存在 → 空存储（首次运行）
    }
    throw error;
  }
  return { mappings: [] };               // 解析失败/形状不对 → 空存储
}
```

教学点：

1. **文件不存在不是错误**：首次运行没有文件，返回空数组。
2. **形状校验**：`isStoreFile` 检查 `mappings` 是数组。文件损坏或格式变化时**优雅降级为空**，而不是让进程崩溃。
   （代价是静默丢数据——更稳妥的做法是备份坏文件，但 MVP 选择简单。）
3. `ENOENT` 精确匹配，其他 IO 错误照常抛出。

### 4.5 类型守卫 isStoreFile

```ts
function isStoreFile(value: unknown): value is StoreFile {
  if (typeof value !== "object" || value === null || !("mappings" in value)) return false;
  const mappings = (value as { mappings: unknown }).mappings;
  return Array.isArray(mappings);
}
```

自定义类型守卫：对 `unknown` 输入做形状检查，通过后 TS 自动收窄类型。

### 4.6 过滤查询

```ts
function matchesFilter(mapping: SessionMapping, filter: SessionFilter | undefined): boolean {
  if (!filter) return true;
  if (filter.chatId !== undefined && mapping.chatId !== filter.chatId) return false;
  if (filter.userId !== undefined && mapping.userId !== filter.userId) return false;
  if (filter.chatType !== undefined && mapping.chatType !== filter.chatType) return false;
  return true;
}
```

`listSessionMappings` 支持按 chatId / userId / chatType 过滤。
由于 JSON 全量在内存，过滤是线性扫描——数据量小完全够用。

## 5. 数据流全景

```
getHost(首次) ──► store.getSessionMapping(key) ──► 命中？恢复 sessionFile : 新建
                  └─► persistHost ──► store.setSessionMapping（upsert）
deleteMapping ──► store.deleteSessionMapping
/sessions ─────► store.listSessionMappings → sessions 卡片
卡片切换 ─────► store.getSessionMapping(target) → switchToMapping
```

## 8. 小结

| 概念 | 实现 |
|---|---|
| 接口抽象 | FeishuStore，业务只依赖接口 |
| 工厂 | createStore 按配置选实现 |
| 串行写 | Promise 链锁（read-modify-write 防竞态） |
| upsert | findIndex + push/replace |
| 容错读 | ENOENT/坏文件 → 空存储 |
| 占位 | SQLite 语义化报错 |

**教学要点**：
1. 「接口先行 + 工厂切换」让存储实现可替换。
2. JSON 存储的并发写必须串行化——read-modify-write 是经典竞态。
3. 存储容错：外部数据（文件）可能损坏，系统要优雅降级。
