# 05-9 附件处理

> 对应源码：`src/attachments/processor.ts`、`src/attachments/mime.ts`、`src/attachments/temp-files.ts`

## 1. 角色定位

用户可能在飞书里发图片、文件、音频、视频。Pi 需要的是：
- 文本（放进 prompt）
- 图片（base64，给支持视觉的模型）

附件处理就是把「飞书文件」翻译成「Pi 能用的输入」并分门别类。

## 2. 决策树（processor.ts 核心）

```ts
export async function processAttachments(options): Promise<ProcessedAttachments> {
  const images: ImageInput[] = [];
  const notes: string[] = [];

  for (const resource of options.message.resources) {
    if (resource.type === "sticker") continue;                    // ① 表情包直接跳过

    const fileName = resourceFileName(resource.fileKey, resource.fileName);

    try {
      const buffer = await options.channel.downloadResource(      // ② 下载文件内容
        options.message.messageId, resource.fileKey, resource.type);

      if (resource.type === "image" && options.supportsImages) {  // ③ 图片 + 模型支持 → base64
        images.push({ type: "image", data: buffer.toString("base64"),
                      mimeType: inferMimeType(fileName) });
        continue;
      }

      if (resource.type !== "audio" && resource.type !== "video"  // ④ 小文本文件 → 展开进 prompt
          && buffer.length <= TEXT_SIZE_LIMIT && isLikelyText(buffer)) {
        notes.push(`[Attachment text: ${fileName}]\n${buffer.toString("utf-8")}`);
        continue;
      }

      // ⑤ 其余 → 存临时文件，只给路径说明
      const filePath = await writeTempAttachment(options.config.files.tempDir ?? ".", options.sessionKey, fileName, buffer);
      notes.push(`[Attachment saved: ${fileName} -> ${filePath}]`);
    } catch (error) {
      // ⑥ 下载/处理失败：不中断，记录说明
      notes.push(`[Attachment failed: ${fileName}: ${message}]`);
    }
  }

  return { images, notes };
}
```

## 3. 分支逻辑讲解

### ① 跳过表情包（sticker）
表情包对模型没有价值，直接跳过，节省下载。

### ② 下载
`channel.downloadResource` 返回 `Buffer`。**一次下载决定后续所有分支**，
所以下载在 try 里——下载失败走 catch 分支（记 note，不中断整条消息）。

### ③ 图片 → base64
条件：`type === "image"` **且** 当前会话模型 `supportsImages()`。

```ts
if (resource.type === "image" && options.supportsImages) {
  images.push({ type: "image", data: buffer.toString("base64"), mimeType: inferMimeType(fileName) });
  continue;
}
```

如果模型不支持图片，这张图会掉进下面的分支——根据是否文本决定展开还是存临时文件。
这就是「**能力探测驱动降级**」：模型强则吃原图，模型弱则降级处理。

`mimeType` 用 `inferMimeType(fileName)` 从扩展名推断（mime.ts）：

```ts
const MIME_BY_EXTENSION: Record<string, string> = {
  png: "image/png", jpg: "image/jpeg", gif: "image/gif", webp: "image/webp", ...
};
export function inferMimeType(fileName: string): string {
  const extension = fileName.split(".").pop()?.toLowerCase() ?? "";
  return MIME_BY_EXTENSION[extension] ?? "application/octet-stream";
}
```

### ④ 小文本 → 内容展开
条件：不是音频/视频（避免把媒体当文本读）、大小 ≤ 32KB、内容疑似文本。

```ts
const TEXT_SIZE_LIMIT = 32 * 1024;   // 32KB

export function isLikelyText(buffer: Buffer): boolean {
  return !buffer.subarray(0, 4096).includes(0);   // 前 4KB 无 NUL 字节 ≈ 文本
}
```

**isLikelyText 的启发式**：二进制文件通常含 NUL 字节（0x00），文本几乎不含。
只看前 4096 字节就够判断，性能好。

符合条件 → 内容直接织进 prompt：
```ts
notes.push(`[Attachment text: ${fileName}]\n${buffer.toString("utf-8")}`);
```

**这是「小文件进上下文」策略**——用户发个小脚本，模型直接能看内容。

### ⑤ 大文件/其他 → 临时文件
```ts
const filePath = await writeTempAttachment(tempDir, sessionKey, fileName, buffer);
notes.push(`[Attachment saved: ${fileName} -> ${filePath}]`);
```

模型看到的是路径说明（无法读内容，但知道文件在哪、可以调用工具去处理它）。

### ⑥ 失败 → 记录说明
下载失败不中断整条消息处理，记一条 note 让模型知道有附件没处理成功。

## 4. 临时文件安全（temp-files.ts）

```ts
export async function writeTempAttachment(tempDir, sessionKey, fileName, buffer): Promise<string> {
  // ① 文件名消毒：去掉路径注入字符
  const sanitizedName = fileName.replace(/[<>:"/\\|?*\u0000-\u001f]/g, "_");
  // ② 空/特殊名兜底
  const safeName = sanitizedName.length > 0 && sanitizedName !== "." && sanitizedName !== ".."
    ? sanitizedName : "attachment.bin";
  // ③ sessionKey 消毒后作为子目录（防止路径穿越）
  const dir = join(tempDir, sessionKey.replace(/[^a-zA-Z0-9_.-]/g, "_"));
  await mkdir(dir, { recursive: true });
  const filePath = join(dir, safeName);
  await writeFile(filePath, buffer);
  return filePath;
}
```

**文件名和 sessionKey 都来自外部输入，必须消毒**：
- 文件名去掉 `<>:"/\|?*` 和控制字符——防止 `../../etc/passwd` 这种路径注入
- sessionKey 只保留安全字符——防止会话 key 里的 `/` 造成目录穿越

按 sessionKey 分子目录存储，天然隔离各会话的临时文件，清理也方便：

```ts
export async function cleanupTempAttachments(tempDir, sessionKey): Promise<void> {
  const dir = join(tempDir, sessionKey.replace(/[^a-zA-Z0-9_.-]/g, "_"));
  await rm(dir, { recursive: true, force: true });
}
```

## 5. 清理时机

`cleanupTempAttachments` 在三个地方被调用（都是 finally 或命令处理完）：

| 位置 | 时机 |
|---|---|
| `runtime-host.ts` prompt finally | 每次 prompt 结束后 |
| `message-handler.ts` 命令分支后 | 命令处理完 |
| `message-handler.ts` 附件处理前 | 防旧残留（其实每次 prompt 后已清） |

**临时文件的生命周期 = 一次消息处理**。用完即清，不留垃圾。

## 6. 小结

| 资源类型 | 处理策略 | 模型看到什么 |
|---|---|---|
| 表情包 | 跳过 | 无 |
| 图片 + 视觉模型 | base64 传入 | 真图 |
| 图片 + 非视觉模型 | 降级为文件说明 | 路径 |
| 小文本 | 内容展开 | 全文 |
| 大文件/媒体 | 临时文件 | 路径说明 |
| 下载失败 | 记 note | 失败说明 |

**教学要点**：
1. 附件处理是「下载 → 分类 → 转换」流水线，分类条件从上到下优先级递减。
2. 一切外部输入（文件名、sessionKey）都要消毒。
3. 失败不中断主流程——把失败转成模型能看到的说明。
