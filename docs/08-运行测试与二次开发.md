# 08 运行、测试与二次开发

> 对应源码：`package.json`、`test/*`、`src/bin/pi-remote-feishu.ts`

## 1. 环境要求

```json
"engines": { "node": ">=22.19.0" }
```

Node 22+，TypeScript ESM 项目（`"type": "module"`）。

## 2. 本地开发命令

```bash
npm install          # 安装依赖
npm run typecheck    # 类型检查（tsc --noEmit）
npm test             # 跑 vitest 单元测试
npm run build        # 编译到 dist/
```

## 3. 测试体系

### 3.1 测试文件一览

| 测试 | 覆盖点 | 测试对象是否依赖飞书 |
|---|---|---|
| `prompt-queue.test.ts` | 同队列串行 / 跨队列并行 | 否 |
| `conversation-router.test.ts` | 私聊/群聊/群按用户/未@拒绝 | 否 |
| `message-normalizer.test.ts` | 命令识别、去@、prompt 拼装 | 否 |
| `card-actions.test.ts` | 卡片动作分发、身份恢复 | 否 |
| `attachments.test.ts` | 附件分类决策树 | mock channel |
| `send-file-to-chat.test.ts` | 文件校验、发送 | mock channel |
| `json-store.test.ts` | CRUD、过滤、损坏降级、并发写 | 否 |
| `config.test.ts` | 配置解析合并默认值 | 否 |

**关键特点：除 attachments / send-file 外，绝大多数测试零外部依赖**。
这得益于 `FeishuChannel` 接口抽象——mock 一个接口比 mock 整个 SDK 容易得多。

### 3.2 测试能教你的

1. **fixture 工厂**：`config()` / `message()` 辅助函数，让每个用例只写差异
2. **行为断言而非实现断言**：测「queue 顺序」而不是「queue 内部结构」
3. **可测试性来自接口**：通道、存储全部接口化

## 4. 如何给这个项目加功能

### 4.1 加一个新命令（以 `/time` 为例）

```ts
// ① types.ts：FeishuCommand 加 "time"
// ② message-normalizer.ts：COMMANDS 集合加 "time"
// ③ message-handler.ts：handleCommand 加分支
if (command.name === "time") {
  await options.channel.sendText(options.input.chatId, `当前时间：${new Date().toLocaleString()}`);
  return true;
}
// ④ 需要的话在 help 卡片里加一行
```

### 4.2 加一个工具（以 `fetch_url` 为例）

```ts
// ① tools/ 下新建文件，参照 send-file-to-chat.ts
export function createFetchUrlTool(config): ToolDefinition<...> {
  return {
    name: "fetch_url",
    label: "Fetch URL content",
    description: "Fetch a URL and return its text content.",
    parameters: Type.Object({ url: Type.String() }),
    async execute(_toolCallId, params) {
      // 注意：如果是「发回飞书」类工具，用 getFeishuContext()
      return { content: [{ type: "text", text: "..." }], details: undefined };
    },
  };
}

// ② runtime-host.ts 的 extensionFactory 里注册
factory(pi) {
  pi.registerTool(createSendFileToChatTool(options.config));
  pi.registerTool(createFetchUrlTool(options.config));
}
// ③ extensions/index.ts 同步注册（让 TUI 会话也能用）
```

### 4.3 加一张新卡片

```ts
// ① cards/ 下新建文件，用 common.ts 的组件拼
export function buildXxxCard(options): JsonObject { ... }
// ② 在命令/卡片动作里 sendCard
// ③ 按钮 value 记得带 cmd 字段，并在 card-actions.ts 里处理
```

### 4.4 替换存储为 SQLite

```ts
// ① store/sqlite-store.ts：实现 FeishuStore 接口
export class SqliteFeishuStore implements FeishuStore { ... }
// ② store.ts：把占位报错换成实现
if (config.sessions.store === "sqlite") {
  return new SqliteFeishuStore(config);
}
```

业务代码零改动——接口抽象的回报。

## 5. 改进建议清单（按性价比排序）

### P0（安全/正确性）
1. **给 `getHost` 加创建锁**：并发首次访问同一 sessionKey 时防双创建。
   ```ts
   private pendingHosts = new Map<string, Promise<ManagedSessionHost>>();
   async getHost(sessionKey, identity) {
     const existing = this.pendingHosts.get(sessionKey);
     if (existing) return existing;
     const promise = this.createHost(sessionKey, identity).finally(() => this.pendingHosts.delete(sessionKey));
     this.pendingHosts.set(sessionKey, promise);
     return promise;
   }
   ```
2. **Webhook transport**：设计文档 Phase 5 规划的验签、URL challenge、事件解密。
3. **权限卡未点击的审计**：超时后记录日志，方便追踪未响应确认。

### P1（体验）
4. **定时调用 `evictIdle`**：加 setInterval，避免空闲会话常驻内存。
5. **卡片动作耗时操作后台化**：switchSession/deleteMapping 较慢时先回 ACK 再执行。
6. **`/stop` 在卡片上即时反馈**：abort 后更新停止卡为「已取消」。

### P2（规模）
7. **SQLite store**：支持多进程/审计/大数据量。
8. **结构化日志**：现在都是 console.error，生产建议用 pino 等。
9. **多租户**：tenantKey 字段已预留，需要时引入 tenant router。

## 6. 部署注意点

1. **长连接进程守护**：用 pm2 / systemd 守护 `pi-remote-feishu serve`，崩溃自动拉起
2. **凭证安全**：appSecret 放环境变量或用户级配置，别进版本库
3. **临时目录**：确认 tempDir 可写、有清理策略（当前每次 prompt 后清理）
4. **白名单**：生产环境建议配置 `allowUsers` / `allowChats`，把 bot 限制在受控范围
5. **日志**：log-level 从 info 起排障；注意 SDK 日志不打印 appSecret

## 7. 面试/讲解时的 90 秒版本

> 「这个项目把飞书变成 Pi Agent 的远程交互入口。
> 核心挑战是 Pi 的运行时是单会话模型，而飞书是多用户多群的——
> 所以我按 sessionKey 做了会话隔离：每个会话独立 runtime、独立串行队列、
> 独立活跃任务标记，用 AsyncLocalStorage 传递当前请求上下文，保证流式输出、
> 停止操作和权限确认都不会串线。
> 对外，飞书 SDK 被封装成一个干净接口；对内，Pi 的 UI 上下文被桥接成飞书卡片，
> 权限确认在远程也能用。模型生成的文件通过注册的 send_file_to_chat 工具直接发回聊天。
> 整个项目不改 Pi 核心，是一个独立可发布的扩展包。」
