第三部分 · 面试准备

02 架构亮点与设计模式

面试官真正关心的不是用了多少模式，而是你能不能把问题、方案和取舍讲清楚。

表达原则

不要说“我用了某某设计模式”。先说问题，再说为什么普通写法会出错，最后说当前设计如何限制复杂度。

亮点总览

亮点解决的问题面试价值
会话级 runtime飞书多用户映射到 Pi 单会话模型系统边界和状态隔离
per-session queue同会话串行，不同会话并行并发控制粒度
远程 UI 桥接Pi confirm/select 迁移到飞书卡片异步交互建模
AsyncLocalStorage工具调用拿到当前飞书上下文上下文传播
受控文件回传模型生成文件安全发回飞书安全边界
按需 skill 加载扩展飞书能力但避免工具膨胀可扩展性和上下文成本

1. 会话级 runtime

问题

飞书里同一时间可能有多个私聊和多个群聊，而 Pi runtime 更接近一个本地会话。如果共用一个 runtime，上下文、停止操作、权限确认和流式输出都会混在一起。

方案

按 sessionKey 创建 SessionHost，每个 host 拥有独立 runtime、queue、activeRun。

面试话术

“我没有把飞书消息直接丢给一个全局 Agent，而是先把飞书世界里的用户和群映射成会话 key。每个 key 都是一个隔离单元，这样状态管理和并发控制可以统一收敛到 SessionHost。”

2. per-session queue

问题

同一会话里两条消息并发执行会写乱上下文；但如果用全局锁，一个群里的长回复会阻塞所有人。

方案

每个 SessionHost 内维护一个 PromptQueue。同 key 串行，不同 key 并行。

面试话术

“锁的粒度等于隔离的粒度。同一个会话必须串行，因为上下文是顺序敏感的；不同会话必须并行，否则远程 Agent 会变成单线程客服。”

3. 远程 UI 桥接

问题

Pi 的权限确认原本发生在本地 UI，但飞书用户在手机上，不能回到终端点确认。

方案

把 ExtensionUIContext.confirm/select 转成飞书交互卡片。卡片发出时登记 pending dialog，用户点击后 resolve 对应 Promise。

面试话术

“我把远程按钮点击建模成本地 Promise 的完成。Pi 侧仍然像等待 UI 一样写逻辑，但真实交互已经换成飞书卡片。”

4. AsyncLocalStorage 上下文传播

问题

模型调用 send_file_to_chat 时，工具函数并没有显式收到 chatId，但它必须知道文件要发回哪个飞书会话。

方案

在 RuntimeHost 执行 prompt 时用 AsyncLocalStorage.run 注入当前飞书上下文，工具内部再读取。

面试话术

“我没有把 chatId 暴露给模型参数，也没有用全局变量，而是用异步上下文传播。它和一次请求绑定，可以天然适配并发场景。”

5. 受控文件回传

问题

Agent 可能生成图片、报告、压缩包等文件，但模型输出的路径不能被完全信任。

方案

send_file_to_chat 只允许发送白名单目录下、大小合规、确认为文件的路径。发送目标来自当前飞书上下文，而不是模型自己指定。

面试话术

“我把模型也当作不可信输入处理。文件路径由模型提供，但发送范围由配置和运行时上下文限制。”

6. 按需 skill 加载

问题

飞书 CLI 能力很多，如果全部变成常驻工具，会增加上下文体积，也可能让模型绕过桥接服务重复发送消息。

方案

只有检测到 lark-cli 已安装时才加载 lark-doc-cli 和 lark-im-readonly skills，并通过提示词和命令 guard 禁止 IM 写操作。

面试话术

“skill 是知识和工作流，tool 是可调用能力。v1 让文档和只读查询通过 skill 按需出现，但 IM 写入仍然收敛到桥接层，避免重复发送。”

设计模式对应表

模式或范式项目位置不要生硬背诵，应该这样讲
FacadeRuntimeHost封装 Pi SDK 初始化、prompt、abort、清理
StrategybuildSessionKey群聊共享和按人隔离由配置决定
AdapterFeishuChannel、createFeishuUIContext把飞书 SDK 和 Pi UI 接口互相适配
Observerstream-renderer订阅 Pi session 事件并渲染为飞书输出
Composition Rootbin/pi-remote-feishu.ts依赖在入口集中装配，业务层只依赖接口
Defensive Programmingsend-file-to-chat、附件处理外部消息和模型输出都要校验
本节小结

真正值得重点讲的是前四个亮点：会话级 runtime、per-session queue、远程 UI 桥接、AsyncLocalStorage。它们能体现你对并发、状态和边界的理解。
