💡 测试能教你的三件事
  1. fixture 工厂：config() / message() 辅助函数，让每个用例只写差异
  2. 行为断言而非实现断言：测「queue 顺序」而不是「queue 内部结构」

4. 改进建议清单（按性价比排序）

P0（安全/正确性）

  1. 给 getHost 加创建锁：并发首次访问同一 sessionKey 时防双创建。 
    private pendingHosts = new Map<string, Promise<ManagedSessionHost>>();
async getHost(sessionKey, identity) {
  const existing = this.pendingHosts.get(sessionKey);
  if (existing) return existing;
  const promise = this.createHost(sessionKey, identity)
    .finally(() => this.pendingHosts.delete(sessionKey));
  this.pendingHosts.set(sessionKey, promise);
  return promise;
}
  2. Webhook transport：设计文档 Phase 5 规划的验签、URL challenge、事件解密。
  3. 权限卡未点击的审计：超时后记录日志，方便追踪未响应确认。

P1（体验）

  1. 定时调用 evictIdle：加 setInterval，避免空闲会话常驻内存。
  2. 卡片动作耗时操作后台化：switchSession/deleteMapping 较慢时先回 ACK 再执行。
  3. /stop 在卡片上即时反馈：abort 后更新停止卡为「已取消」。

P2（规模）

  1. SQLite store：支持多进程/审计/大数据量。
  2. 结构化日志：现在都是 console.error，生产建议用 pino 等。
  3. 多租户：tenantKey 字段已预留，需要时引入 tenant router。

5. 部署注意点

  1. 长连接进程守护：用 pm2 / systemd 守护 pi-remote-feishu serve，崩溃自动拉起
  2. 凭证安全：appSecret 放环境变量或用户级配置，别进版本库
  3. 临时目录：确认 tempDir 可写、有清理策略
  4. 白名单：生产环境建议配置 allowUsers / allowChats，把 bot 限制在受控范围
  5. 日志：log-level 从 info 起排障；注意 SDK 日志不打印 appSecret
