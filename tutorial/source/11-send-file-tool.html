11 文件回传工具（send_file_to_chat）

注册给模型的工具：生成文件后主动发回飞书——三层安全防线 + AsyncLocalStorage 实战。

1. 角色定位

这是一个注册给 Pi 模型调用的工具：当模型生成了文件（报告、代码、图片……）， 它可以主动调用 send_file_to_chat 把文件发回当前飞书聊天。

模型生成文件 /tmp/report.md
  └─► 调用 send_file_to_chat({ filePath: "/tmp/report.md", fileName: "报告.md" })
        ├─► 校验路径在允许目录内
        ├─► 校验是文件、大小不超限
        ├─► 从 FeishuContext 拿到 channel + chatId
        ├─► channel.sendFile(chatId, path, name)
        └─► 返回标准 tool result

2. 参数 Schema（TypeBox）

const sendFileSchema = Type.Object({
  filePath: Type.String({ description: "Local file path to send to the current Feishu chat" }),
  fileName: Type.Optional(Type.String({ description: "Display file name in Feishu" })),
});

用 TypeBox 定义参数 schema，Pi 会把 schema 描述给模型，并校验模型传参。Type.Optional 让 fileName 可选。

3. 安全校验（validateFile）—— 三层防线

async function validateFile(filePath: string, config: FeishuConfig): Promise<string> {
  const resolvedPath = resolve(filePath);
  // ① 路径必须在允许的输出目录内
  if (!config.files.allowedOutputDirs.some((dir) => isUnderPath(resolvedPath, dir))) {
    throw new Error("File is outside allowed output directories");
  }
  // ② 必须是文件（不能是目录）
  const statResult = await stat(resolvedPath);
  if (!statResult.isFile()) {
    throw new Error("Path is not a file");
  }
  // ③ 大小限制
  if (statResult.size > config.files.maxUploadBytes) {
    throw new Error(`File exceeds upload limit (${config.files.maxUploadBytes} bytes)`);
  }
  return resolvedPath;
}

isUnderPath：防目录穿越

function isUnderPath(target: string, root: string): boolean {
  const resolvedTarget = resolve(target);
  const resolvedRoot = resolve(root);
  const relativePath = relative(resolvedRoot, resolvedTarget);
  return relativePath === "" || (!relativePath.startsWith("..") && !isAbsolute(relativePath));
}

判断原理：path.relative(root, target) 如果返回 .. 开头，说明 target 在 root 外面。 特殊处理 relativePath === ""（target 就是 root 本身）。

⚠️ 为什么「模型输入」也要校验？

模型输入被当作不可信输入对待。模型也可能被骗、出错、或产生恶意输出。 三道防线：路径白名单（防止读系统文件）→ 类型校验（必须是文件）→ 大小限制（防止上传超大文件）。

💡 工具不知道自己在哪个 chat——上下文告诉它
  • 在飞书请求期间调用（runWithFeishuContext 包裹的 prompt 内）→ 拿到 { channel, chatId }
  • 在 TUI/其他场景调用（无飞书上下文）→ 优雅返回失败说明

这个设计的巧妙之处：工具函数本身不依赖任何全局状态， 只依赖异步上下文，因此可以在任何 runtime 里安全注册（TUI 会话、飞书会话都能用同一个工具定义）。

5. 发送与结果

try {
  const filePath = await validateFile(params.filePath, config);
  await context.channel.sendFile(context.chatId, filePath, params.fileName ?? basename(filePath));
  return {
    content: [{ type: "text", text: `Sent file to Feishu: ${params.fileName ?? basename(filePath)}` }],
    details: undefined,
  };
} catch (error) {
  const message = error instanceof Error ? error.message : String(error);
  return {
    content: [{ type: "text", text: `Failed to send file to Feishu: ${message}` }],
    details: undefined,
  };
}
  • 失败也返回标准 tool result（不抛异常），让模型知道自己哪里错了可以重试
  • 结果文本里带文件显示名，模型可以转述给用户

6. 两个注册点（双通道）

这个工具在两处注册：

注册点位置场景
RuntimeHost 创建时runtime-host.ts extensionFactory飞书 transport 进程内，每个会话的 runtime 都有
Pi Extension 入口extensions/index.tsPi 本体（TUI 会话）也有，配置存在时注册

两个入口殊途同归：工具定义相同，行为相同（TUI 下调用会返回「不在飞书请求中」）。

7. Prompt 指引（promptGuidelines）

promptGuidelines: [
  "When you create a deliverable file for a Feishu user, call send_file_to_chat with the final local file path.",
  "Only send files that already exist and are relevant to the user's request.",
],

工具定义里带行为指引，Pi 会把它注入模型上下文—— 告诉模型「什么时候该主动发文件」「什么不该发」。这是让模型行为符合预期的低成本手段。
