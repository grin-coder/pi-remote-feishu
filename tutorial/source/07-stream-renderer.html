07 流式渲染（StreamRenderer）

把 Pi 的事件流翻译成飞书卡片里的流式文本——一个「带状态的格式化」范例。

🎯 本节目标
  • 理解事件订阅 + 增量追加的渲染模型
  • 看懂思考块引用格式化的「逐字符状态机」
  • 掌握订阅与运行的配对（finally 取消订阅）
📂 本节源码

src/bridge/stream-renderer.ts（114 行）

1. 角色定位

Pi 在生成回复时，会持续发出事件（文本增量、思考增量、工具开始/结束、错误、重试……）。 飞书 SDK 支持流式更新一条消息。stream-renderer 就是这两者之间的翻译官。

2. 事件订阅：createSessionEventForwarder

核心是一个 session.subscribe 回调，按事件类型分流处理：

function createSessionEventForwarder(session, writer, config) {
  let inThinking = false;          // 当前是否在思考块内
  let needsQuotePrefix = true;     // 下一行是否需要补引用前缀

  return session.subscribe((event) => {
    if (event.type === "message_update") {
      const messageEvent = event.assistantMessageEvent;
      if (!messageEvent) return;
      if (messageEvent.type === "text_delta") {
        void writer.append(closeThinking() + (messageEvent.delta ?? ""));
      } else if (messageEvent.type === "thinking_delta" && config.rendering.showThinking !== "hide") {
        ...思考增量的引用格式化...
      } else if (messageEvent.type === "error") {
        void writer.append(`${closeThinking()}Model returned an error.`);
      }
      return;
    }
    ...工具事件、compaction、重试...
  });
}

3. 三种事件流的分流逻辑

3.1 文本增量（text_delta）—— 主输出

void writer.append(closeThinking() + (messageEvent.delta ?? ""));

模型输出一个字符块，就追加到飞书消息。closeThinking() 负责在「思考 → 正文」切换时插入换行分隔。

3.2 思考增量（thinking_delta）—— 可配置

根据 config.rendering.showThinking 有三种策略：

配置行为
"hide"不输出（模型思考过程不可见）
"plain"原文输出（无修饰）
"quote"（默认）逐行加 > 前缀，变成引用块

引用格式化的实现很妙——逐字符处理：

for (const character of delta) {
  if (needsQuotePrefix) {
    output += "> ";
    needsQuotePrefix = false;
  }
  output += character;
  if (character === "\n") {
    needsQuotePrefix = true;    // 换行后下一行需要重新加前缀
  }
}
inThinking = true;
void writer.append(output);
💡 为什么逐字符处理？

流式增量可能在任意位置断开（一行可能被切成多个 delta）。 逐字符处理 + 两个布尔状态变量，保证无论增量怎么切分，引用前缀都正确。 这是一个「流式状态机」的教学范例：用状态跨事件维护格式化上下文。

3.3 工具事件（可选显示）

if (!config.rendering.showToolEvents) return;   // 配置关闭则完全不显示

if (event.type === "tool_execution_start") {
  void writer.append(`${closeThinking()}\nRunning tool: ${event.toolName ?? "unknown"}\n`);
} else if (event.type === "tool_execution_update") {
  void writer.append(`${closeThinking()}${String(event.partialResult ?? "")}`);
} else if (event.type === "tool_execution_end") {
  void writer.append(`${closeThinking()}${event.isError ? "Tool failed" : "Tool completed"}\n`);
} else if (event.type === "compaction_start") {
  void writer.append(`${closeThinking()}Compacting context...\n`);
} else if (event.type === "auto_retry_start") {
  void writer.append(`${closeThinking()}Retrying (${event.attempt ?? "?"}/${event.maxAttempts ?? "?"})...\n`);
}

用户可以看到 Pi 在「跑工具、压缩上下文、自动重试」——这对调试和信任都很重要。 每个事件都先 closeThinking()，保证思考块在工具输出前正确闭合。

4. 渲染入口：renderPromptStream

export async function renderPromptStream(options: StreamRenderOptions): Promise<void> {
  if (options.config.rendering.mode === "text") {
    // 纯文本模式：不流式，直接跑完
    await options.runPrompt();
    return;
  }

  await options.channel.streamMarkdown(
    options.chatId,
    async (writer) => {
      const unsubscribe = createSessionEventForwarder(options.session, writer, options.config);
      try {
        await options.runPrompt();       // 跑 prompt，事件会实时喂给 writer
      } finally {
        unsubscribe();                   // 无论成败取消订阅
      }
    },
    options.replyTo ? { replyTo: options.replyTo } : undefined,
  );
}

教学点：

  1. 订阅与运行的配对：先订阅，后运行，finally 里取消订阅。保证 prompt 报错时不会残留订阅器。
  2. streamMarkdown 的 producer 模式：飞书 SDK 反复调用 writer.append 更新卡片。
  3. text 模式快捷路径：rendering.mode === "text" 时跳过流式，直接跑。

5. 流式状态机的完整视图

事件流（时间轴）:
text_delta "你"
text_delta "好"        ─► 正文：直接追加 "你好"
thinking_delta "让我想想\n"
thinking_delta "先检查" ─► 引用块："> 让我想想\n> 先检查"
tool_execution_start   ─► 关闭思考块 + "\nRunning tool: grep\n"
text_delta "答案是X"   ─► closeThinking() 补空行 + "答案是X"
error                  ─► "Model returned an error."

关键：inThinking / needsQuotePrefix 两个状态变量跨事件工作， 无论增量怎么切分，输出格式始终正确。

✅ 本节小结
事件类型渲染策略
text_delta直接追加
thinking_deltahide / plain / quote（逐字符引用状态机）
tool / compaction / retry可选显示，先闭合思考块
error固定错误提示

教学要点：流式渲染的本质是「事件 → 带状态的格式化 → 增量追加」。 状态（inThinking、needsQuotePrefix）必须跨事件维护，这是和普通字符串拼接最大的区别。
