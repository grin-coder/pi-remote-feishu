1. 卡片是什么

飞书卡片是 JSON 结构，通过 sendCard(chatId, card) 发送，支持按钮、下拉菜单等交互。 卡片被点击后，飞书回调携带按钮的 value（自定义数据）到 WebSocket，由 card-actions.ts 处理。

发送方                          点击方
buildXxxCard(card JSON) ──► 飞书渲染 ──► 用户点按钮
                                          │ value: {cmd:"stop", sessionKey:"dm:alice"}
                                          ▼
                                    card-actions.handleCardAction
💡 教学点

按钮 value 是卡片与后端通信的信使——所有命令都编码在 value 里。

2. 卡片构建器（src/cards/）

2.1 common.ts：基础组件库

export function textBlock(content: string): JsonObject {
  return { tag: "div", text: { tag: "lark_md", content } };   // markdown 文本块
}

export function button(text: string, value: JsonObject, type = "default"): JsonObject {
  return { tag: "button", text: { tag: "plain_text", content: text }, type, value };
}

export function card(title, template, elements): JsonObject {
  return { config: { wide_screen_mode: true },
           header: { title: { tag: "plain_text", content: title }, template },
           elements };
}

还有 actions（按钮组）、selectMenu（下拉菜单）、noteBlock（灰色注释）。 这是组合模式：业务卡片用基础组件搭出来，不用重复写原始 JSON。

2.2 六张业务卡片

文件卡片用途
help.ts帮助卡/help，列出命令和文件能力
models.ts模型选择卡/models，列出模型 + 使用按钮
sessions.ts会话管理卡/sessions，列出/切换/新建/删除会话

2.3 任务状态卡（stop.ts）—— 一张卡的两个生命阶段

// 生成中：黄色 + 停止按钮
export function buildStopCard(options): JsonObject {
  return card("Pi 正在处理", "yellow", [
    textBlock([...正在回复谁、会话、模式...].join("\n")),
    actions([button("停止生成", { cmd: "stop", sessionKey: options.sessionKey }, "danger")]),
  ]);
}

// 结束后：灰色，无按钮
export function buildStopDoneCard(title: string, message: string): JsonObject {
  return card(title, "grey", [textBlock(message), noteBlock("这张状态卡会保留在当前聊天中。")]);
}

message-handler 里先发 stopCard，结束后用 updateCard(stopCard.messageId, doneCard) 原地更新同一张卡。 这是飞书卡片模式的核心：用卡片状态机替代多条消息，聊天区不刷屏。

3. 按钮 value 协议（card-actions 的契约）

所有按钮 value 都遵循 { cmd: string, ... } 结构：

cmd附加字段动作
stopsessionKey中断该会话生成
sessionaction: new/switch/delete、targetSessionKey会话管理
modelprovider、modelId、thinkingLevel、sessionKey切换模型
permissiondialogId、choice权限确认

4. handleCardAction：卡片动作分发

export async function handleCardAction(options): Promise<void> {
  const value = options.event.actionValue;
  const cmd = readString(value, "cmd");

  if (cmd === "permission") {
    // 权限确认：resolve 挂起的 Promise（见 UI 桥接一章）
    if (options.event.token) {
      await options.updateCardByToken(options.event.token, buildResolvedPermissionCard(value));
    } else {
      buildResolvedPermissionCard(value);
    }
    return;
  }

  const sessionKey = readString(value, "sessionKey");
  if (!sessionKey) return;

  if (cmd === "stop") {
    await options.manager.abort(sessionKey);
    return;
  }

  // 需要 host 的操作：先解析身份（从 sessionKey 或 store 映射）
  const identity = await identityFromStore(options.config, options.store, options.event, sessionKey);

  if (cmd === "session") {
    const action = readString(value, "action");
    if (action === "new") await options.manager.newSession(sessionKey, identity);
    else if (action === "switch") { ... await options.manager.switchToMapping(...) }
    else if (action === "delete") { ... await options.manager.deleteMapping(...) }
    return;
  }

  if (cmd === "model") {
    const host = await options.manager.getHost(sessionKey, identity);
    const registry = new ModelRegistry(host.runtime.services.modelRuntime);
    const provider = readString(value, "provider");
    const modelId = readString(value, "modelId");
    const thinkingLevel = readString(value, "thinkingLevel") ?? "off";
    if (provider && modelId) {
      const model = registry.find(provider, modelId);
      if (model) {
        await host.runtime.session.setModel(model);
        host.runtime.session.setThinkingLevel(thinkingLevel as ...);
      }
    }
    // 用 token 原地更新模型卡片，显示新选择
    if (options.event.token) { await options.updateCardByToken(options.event.token, buildModelsCard({...})) }
  }
}

4.1 教学点：身份恢复（两级兜底）

卡片动作可能来自没有 host 的会话（比如进程重启后点旧卡片）。identityFromStore 负责从 store 的会话映射里恢复：

async function identityFromStore(config, store, event, sessionKey): Promise<FeishuIdentity> {
  const mapping = await store.getSessionMapping(sessionKey);
  if (!mapping) return identityFromSessionKey(config, event, sessionKey);  // 兜底：从 key 推断
  return { appId: config.appId, chatType: mapping.chatType, chatId: mapping.chatId,
           userOpenId: mapping.userId ?? event.userOpenId ?? "unknown", ... };
}

// 从 key 推断的兜底逻辑
function identityFromSessionKey(config, event, sessionKey): FeishuIdentity {
  const group = sessionKey.startsWith("group:");
  const groupUser = sessionKey.startsWith("group-user:");
  return { appId: config.appId,
           chatType: group || groupUser ? "group" : "private",
           chatId: event.chatId, userOpenId: event.userOpenId ?? "unknown" };
}

两条恢复路径：精确（store 映射）→ 兜底（key 前缀推断）。

4.2 教学点：模型切换

const registry = new ModelRegistry(host.runtime.services.modelRuntime);  // 从 runtime 拿模型注册表
const model = registry.find(provider, modelId);                          // 校验模型存在
if (model) {
  await host.runtime.session.setModel(model);
  host.runtime.session.setThinkingLevel(thinkingLevel as ...);
}

先查后设：模型不存在（已被配置移除）就不动，避免设置无效模型。

5.2 会话切换的 key 语义

button("切换", { cmd: "session", action: "switch", sessionKey: current, targetSessionKey: mapping.sessionKey })

切换/删除按钮的 sessionKey 是当前会话，targetSessionKey 是目标会话。 因为操作是「以当前 host 为容器，切换/删除目标会话」。
