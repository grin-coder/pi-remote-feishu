1. 角色定位

SessionHostManager 是所有 SessionHost 的管理员，管三件事：

  1. 查找/创建 host（内存 Map + 磁盘 store 恢复）
  2. 生命周期（新建会话、切换会话、删除、空闲回收）
  3. 持久化（每次变更同步到 store）
export class SessionHostManager {
  private readonly hosts = new Map<string, ManagedSessionHost>();  // sessionKey → host
  private readonly config: FeishuConfig;
  private readonly store: FeishuStore;
  private readonly channel: FeishuChannel;
}

依赖注入三件套：config、store、channel。所有依赖通过构造函数传入，不 new 依赖（组合根在 bin 里统一创建）。

2. getHost：查找或创建（核心方法）

async getHost(sessionKey: string, identity: FeishuIdentity): Promise<ManagedSessionHost> {
  const existing = this.hosts.get(sessionKey);
  if (existing) {
    existing.lastUsedAt = new Date();   // ① 命中缓存：刷新时间戳
    return existing;
  }

  // ② 未命中：尝试从 store 恢复
  const mapping = await this.store.getSessionMapping(sessionKey);
  const cwd = mapping?.cwd ?? this.config.sessions.defaultCwd ?? process.cwd();

  // ③ 创建 runtime host（Pi 运行时）
  const runtimeHost = await createRuntimeHost({
    sessionKey, cwd, config: this.config, channel: this.channel,
    ...(mapping?.sessionFile ? { sessionFile: mapping.sessionFile } : {}),  // 恢复历史会话文件
  });

  const host: ManagedSessionHost = {
    sessionKey,
    runtime: runtimeHost.runtime,
    runtimeHost,
    queue: new PromptQueue(),          // ④ 每个 host 一个全新队列
    lastUsedAt: new Date(),
  };
  this.hosts.set(sessionKey, host);    // ⑤ 入内存

  await this.persistHost(host, identity);  // ⑥ 持久化映射
  return host;
}

2.1 内存与磁盘的双缓存

层存什么作用
内存 Map完整 host（含 runtime、队列）热路径：直接复用，零 IO
磁盘 storesessionKey → { sessionFile, cwd, ... }冷路径：进程重启后恢复

2.2 恢复的语义

如果 store 里有 mapping.sessionFile，createRuntimeHost 用 SessionManager.open() 打开历史会话文件——用户之前的对话历史全回来了。 如果什么都没有，用 SessionManager.create(cwd) 新建。

3. persistHost：持久化映射

private async persistHost(host: ManagedSessionHost, identity: FeishuIdentity): Promise<void> {
  const sessionFile = host.runtime.session.sessionFile;
  if (!sessionFile) return;
  const now = new Date().toISOString();
  const previous = await this.store.getSessionMapping(host.sessionKey);
  await this.store.setSessionMapping({
    sessionKey: host.sessionKey,
    appId: this.config.appId,
    chatType: identity.chatType,
    chatId: identity.chatId,
    cwd: host.runtime.cwd,
    sessionFile,
    createdAt: previous?.createdAt ?? now,   // 首次创建时记 createdAt，之后保留
    updatedAt: now,
    ...(identity.tenantKey ? { tenantKey: identity.tenantKey } : {}),
    ...(identity.chatType === "private" || this.config.sessions.groupScope === "per-user"
      ? { userId: identity.userOpenId }      // 私聊/按用户隔离时记录用户
      : {}),
  });
}
💡 教学点
  1. sessionFile 是「从 runtime 里读出来的」，不是凭空猜的——runtime.session.sessionFile 是 Pi SDK 给的真实会话文件路径。
  2. createdAt 用「上一次的值，没有就现在」——保证创建时间不被重复刷新。
  3. 字段按需附加（tenantKey、userId），保持记录最小。

4. 生命周期操作

4.1 newSession：新建

async newSession(sessionKey: string, identity: FeishuIdentity): Promise<void> {
  const host = await this.getHost(sessionKey, identity);
  await host.runtime.newSession();                // Pi SDK：新建 session
  await host.runtime.session.bindExtensions({});  // 重新绑定扩展（新 session 需要重新注册工具）
  await this.persistHost(host, identity);
}

4.2 switchToMapping：切换到另一个映射

async switchToMapping(sessionKey, targetSessionKey, identity): Promise<boolean> {
  const target = await this.store.getSessionMapping(targetSessionKey);
  if (!target) return false;                     // 目标不存在 → 明确返回失败
  const host = await this.getHost(sessionKey, identity);
  await host.runtime.switchSession(target.sessionFile, { cwdOverride: target.cwd });
  await host.runtime.session.bindExtensions({});
  await this.persistHost(host, identity);
  return true;
}

切换的语义：当前 sessionKey 的 host 被切换到另一个已存在的会话文件。 返回值是 boolean——目标映射不存在就返回 false，调用方（卡片动作）据此决定是否提示。

4.3 abort：中断

async abort(sessionKey: string): Promise<boolean> {
  const host = this.hosts.get(sessionKey);
  if (!host) return false;
  await host.runtimeHost.abort();   // 最终调用 runtime.session.abort()
  return true;
}

只 abort 这个 sessionKey 的 host——这就是「stop 不串线」的实现保证。

4.4 deleteMapping：删除

async deleteMapping(sessionKey: string): Promise<void> {
  const host = this.hosts.get(sessionKey);
  if (host) {
    await host.runtimeHost.dispose();  // 释放 runtime 资源
    this.hosts.delete(sessionKey);
  }
  await this.store.deleteSessionMapping(sessionKey);  // 删磁盘映射
}

内存和磁盘同步清理，避免下次 getHost 又恢复出已删除的会话。

4.5 evictIdle：空闲回收

async evictIdle(now: Date = new Date()): Promise<void> {
  const expired: string[] = [];
  for (const [key, host] of this.hosts) {
    if (now.getTime() - host.lastUsedAt.getTime() > this.config.sessions.idleTtlMs && !host.activeRun) {
      expired.push(key);
    }
  }
  for (const key of expired) {
    const host = this.hosts.get(key);
    if (host) {
      await host.runtimeHost.dispose();
      this.hosts.delete(key);
    }
  }
}
💡 教学点
  1. 先收集再删除——避免在遍历 Map 时删除（迭代器失效问题）。
  2. !host.activeRun 是硬条件——有任务在跑，哪怕超时也不回收。
  3. 回收只清内存，磁盘映射保留，下次消息来了自动恢复。这就是「进程里热数据换页」的思路。

5. 已知竞态：getHost 无锁

getHost 本身存在一个竞态：两条并发消息首次到达同一个新 sessionKey， 可能同时 get 不到、同时创建两个 host。当前代码没有对 getHost 加锁。

不过实际影响有限：handleFeishuMessage 内部 getHost 之后才 queue.enqueue， 而两条消息几乎总是先后进入（同一飞书 chat 的 WebSocket 事件基本有序）。 这是一个已知的待加固点（二次开发篇会给出修复方案）。
