1.2 main：组合根

async function main(): Promise<void> {
  const cli = parseArgs(process.argv.slice(2));
  if (cli.command === "help") { printHelp(); return; }

  const config = loadConfig(cli.config);
  if (config.transport === "webhook") {
    throw createWebhookNotImplementedError();   // webhook 未实现 → 语义化报错
  }

  const channel = createFeishuChannel({...});
  const store = createStore(config);
  const manager = new SessionHostManager({ config, store, channel });

  channel.onMessage((message) => {
    handleFeishuMessage({ config, channel, store, manager, message }).catch((error) => {
      console.error(error instanceof Error ? error.message : String(error));
    });
  });
  channel.onCardAction((event) => {
    handleCardAction({ config, store, manager, event, updateCardByToken: ... }).catch(...);
  });
  channel.onError((error) => { console.error(error.message); });

  await channel.connect();
  console.error(`Feishu bot connected${channel.botName ? ` as ${channel.botName}` : ""}.`);

  await new Promise<void>((resolvePromise) => {
    const shutdown = () => {
      channel.disconnect().finally(resolvePromise);
    };
    process.once("SIGINT", shutdown);
    process.once("SIGTERM", shutdown);
  });
}

1.3 教学点：组合根（Composition Root）

所有依赖（config、channel、store、manager）都在 main 里创建并注入。 模块之间不互相 new——它们只依赖接口/构造参数。好处：

  • 替换实现容易（换 store、换 channel 都不动业务代码）
  • 测试容易（注入 mock）
  • 依赖方向清晰（朝外，不朝内）

1.4 教学点：长连接进程的写法

进程最后挂在一个 Promise 上，只有收到 SIGINT/SIGTERM 才会 disconnect 并退出。 这是「长连接进程」的典型写法：主事件循环常驻 + 信号驱动优雅关闭。

每个回调都 .catch() 处理错误——单个消息处理失败不能杀死整个进程。

2. Pi Extension 加载（src/extensions/index.ts）

import type { ExtensionAPI } from "@earendil-works/pi-coding-agent";
import { loadConfig } from "../config/load-config.js";
import { createSendFileToChatTool } from "../tools/send-file-to-chat.js";

export default function feishuExtension(pi: ExtensionAPI): void {
  pi.registerCommand("feishu", {
    description: "Show Feishu extension status",
    handler: async (_args, ctx) => {
      ctx.ui.notify("Feishu extension is loaded. Start the transport with `pi-feishu serve`.", "info");
    },
  });

  try {
    const config = loadConfig();
    pi.registerTool(createSendFileToChatTool(config));
  } catch {
    pi.on("agent_start", (_event, ctx) => {
      ctx.ui.notify("Feishu config not found; send_file_to_chat is not registered.", "warning");
    });
  }
}

2.1 教学点：优雅降级

配置缺失不崩溃，而是注册一个 agent_start 事件，等 agent 启动后提示一次用户。 「能力不可用时给出明确提示」而不是静默失败——和决策 12（语义化占位）一脉相承。

2.2 package.json 的接线

{
  "name": "pi-feishu",
  "bin": { "pi-feishu": "./dist/bin/pi-feishu.js" },
  "pi": { "extensions": ["./dist/extensions/index.js"] },
  "exports": {
    ".": { "types": "./dist/index.d.ts", "import": "./dist/index.js" },
    "./extension": { "types": "./dist/extensions/index.d.ts", "import": "./dist/extensions/index.js" }
  }
}
  • bin：让 pi-feishu serve 命令可用
  • pi.extensions：告诉 Pi 包管理器加载扩展
  • exports：包的双入口（主入口 + extension 入口）

3. 两个入口如何配合

┌─ 你启动 Pi（TUI）──────────────────────────────┐
│  Pi 发现 package.json 的 pi.extensions          │
│  → 加载 extensions/index.js                     │
│  → 注册 /feishu 命令 + send_file_to_chat 工具    │
└─────────────────────────────────────────────────┘

┌─ 你启动 pi-feishu serve（另一进程）─────────────┐
│  → 连接飞书 WebSocket                           │
│  → 收到消息 → SessionHostManager → RuntimeHost  │
│  → 每个 runtime 创建时也注册 send_file_to_chat   │
└─────────────────────────────────────────────────┘

两个进程各自独立运行：没有飞书连接时 Pi 正常用；飞书连接不依赖 Pi 的 TUI 会话。 工具是「共享能力」，连接是「transport 独有」——这就是第一章说的「嘴和耳朵 vs 手」。

✅ 本节小结
  • bin：组合根 + 长连接 + 信号关闭 + 错误隔离（catch 全部回调）
  • extensions：注册命令/工具 + 配置缺失优雅降级
  • package.json 三件套：bin / pi.extensions / exports
  • 两个进程配合：共享工具能力，独立连接生命周期
